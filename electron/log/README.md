# 日志收集与保留

日志仍通过已有的 `electron-log` 方法调用；这里只调整日志分类、收集和落盘，不调整任务调度、筛选、请求、保存或上架流程。

| 分类     | 收集内容                                                              | 单文件上限 | 类别总容量 | 保留天数      |
| -------- | --------------------------------------------------------------------- | ---------- | ---------- | ------------- |
| system   | 启动、退出、更新、窗口、内存监控、HTTP 故障、渲染进程日志、未捕获异常 | 10 MiB     | 100 MiB    | 7 天，含当天  |
| business | 采集、巡检、1688 图搜、OZON 验证、业务指标、任务进度和结果            | 10 MiB     | 400 MiB    | 14 天，含当天 |

策略常量位于 [file-store.ts](./file-store.ts) 的 `LOG_POLICIES`。两类日志独立执行空间限制，业务高频日志不会挤占系统日志额度。保留天数是最长保留期；容量先达到上限时，提前删除最旧分卷。日志正文合计最多 500 MiB，无法同时保证无限期保留历史。

## 文件位置和写入

目录沿用 `app.getPath('userData')/logs`：

```text
logs/
  2026-11-06.system.<本次启动标识>.000001.txt
  2026-11-06.business.<本次启动标识>.000002.txt
  2026-11-06.business.<本次启动标识>.000003.txt
  2026-11-06.log                  # 兼容旧版
  2026-11-06.old.log              # 兼容旧版轮转
```

所有新文件均用独占创建，之后只追加；不同启动使用不同标识。到达文件上限或跨本地日期后生成新文件，不复用固定 `.old` 名称，不截断当前日志。普通记录在一个分卷内写完；单条超过 10 MiB 的记录按 UTF-8 字符边界跨卷保存。每次写入前检查容量，删除旧分卷后再追加，避免异步写入与轮转竞争。

启动以及跨日后的第一次写入会清理过期文件；每次追加均检查容量。旧日期 `.log/.old.log` 纳入系统日志的保留策略和导出范围，不会改写其内容。历史版本已经覆盖的内容无法恢复。

文件写入、轮转或清理失败会报告到控制台，不向业务调用抛异常；日志初始化具有幂等性。未捕获异常和 Promise 拒绝交给 `electron-log.errorHandler` 统一收集，避免重复注册、重复记录。

## 调用约定

```ts
// 系统运行日志，已有调用方式保持不变。
import log from '../../log/index.js'
log.error('窗口异常退出', error)

// 业务日志，级别与方法保持一致。
import businessLog from '../../log/business.js'
businessLog.info('业务事件', { taskId, phase, goodsId })
```

文件默认记录 `info/warn/error`，控制台开发环境额外显示 `debug`，沿用原有级别策略。每条记录包含本地时间、级别、分类/作用域、进程 ID。错误对象保留堆栈；采集和巡检进度补充任务 ID、任务名称、阶段和计数，同时继续推送原有页面事件。

共享 HTTP 客户端故障记录为系统日志，业务调用方的失败和任务结果记录为业务日志。没有把第三方页面中的全部 `console` 输出或完整请求体纳入收集。

现有“导出全部日志”入口保持不变，会收集所有 `.txt` 分卷及旧 `.log/.old.log`。日期仍放在文件名开头，最近 N 天导出继续可用；文件名包含分类、启动标识和序号，导出时不会重名覆盖。

## 验证

```text
npm run test:logging
npm run test:collection
npm run test:inspection
npm run build:electron
```

日志测试使用临时目录和小容量阈值，检查反复轮转、追加、容量清理、跨日保留、重启、长中文/emoji 记录、旧日志发现及文件系统故障。
